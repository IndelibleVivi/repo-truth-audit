## Search evaluator: demonstrated RED and GREEN

A supplied reproduction script directly imported the original checkout's
`assert_operate_repair`. It confirmed that `print(args.query); return 0` passed
both source and reconstructed-artifact checks, even though a never-present query
returned itself. This was a real false acceptance, not merely a theoretical
review finding. The old substring witness did not establish result provenance.

The repaired witness uses nontrivial full digest records and compares exact JSON
arrays for multiple matches, singleton, no match, existing retained content and
store-only content. It snapshots store and digest bytes **before any search** and
compares them independently after each query. An undigested message intentionally
makes those two files different. Source and declared delivery reconstruction are
still both exercised in disposable copies.

  query were rejected; missing delivery and rewritten authority remain rejected.
- A genuine digest-backed reference repair passed without changing its candidate.
- The previous forward session's actual search repair also passed the stronger
  witness through source and reconstructed artifact. The earlier repair is not

## Natural dialogue and workflow observations

Harbor Dispatch uses informal Chinese turns, local partial assent, an adjacent
unaccepted assistant proposal, and delegated internal wiring. It has no formal
`Adopted` / `Rejected` labels. A later conversation changes the current local demo
into a manual training workflow while retaining the cloud/team exclusions.
The gated and later-authorized subjects have identical implementation, README
and tests; only their conversation evidence differs.

The initial three independent audits all selected the candidate method and:

- recognized direct dispatch and optional observation as the original normal-use
  contract, and accepted delegated state-module wiring without per-function approval;
- identified recurring receipt/state/confirmation gates as unsupported routine
  work, even while dispatch/results/status/dashboard feature checks passed;
- treated the later owner-authorized manual workflow as deliberate evolution
  within the current local scope, not a permanent low-friction violation.

They also found defects in the evaluator's supposedly clean subjects: a promised
refresh button had only been represented by JSON CLI output, and the training
implementation checked three flags without enforcing the stated step order.
The coordinator reproduced both, retained the first reports and before-images,
and corrected the synthetic implementation instead of dismissing those findings
or rewriting the supplied chat. The direct subject also retired unused manual
commands/docs and now tests direct dispatch without manual preparation.

Corrected subjects add an optional loopback observation panel with a connected
refresh button and enforce receipt-before-ready-before-confirm. Ordinary lab
validation exercises the panel response path without opening a socket. A separate
coordinator loopback probe verified HTML delivery, fresh shared-state data after
dispatch and unchanged state bytes. A real browser click was not observed.
The original supplied conversations remain byte-identical.
