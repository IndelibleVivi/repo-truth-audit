## What changes from v0.1.0

The Audit-only Skill becomes a progressive Audit / Plan / Operate workflow.
Plain inspection remains read-only. Planning stops before target edits. An
explicit finite structural-change request can continue through implementation,
real callers and selectors, related tests/docs, required legacy retirement,
recovery-aware checkpoints and acceptance.

The operation remains responsible for the whole agreed goal. A verified first
increment is a checkpoint, not completion. Applicable Behavior, Structure,
Delivery and Usefulness checks distinguish a working transition from a finished
change and test whether the original development friction eased.

## Reliability and evidence

One declared eight-file payload now governs validation, digests, staging and
installed comparison. Normal import-generated bytecode does not alter or enter
the installable payload; undeclared source/executable entries are rejected.
An optional bounded byte checker validates cited bytes only, never permission,
semantic correctness or completion.

The [forward receipt](../forward-0.2.0-receipt.md) preserves historical evidence,
reconciles the original copied bytecode residue and records clean-payload actual
Plan and single-request Operate observations. The latter completed a finite
synthetic change, built its declared artifact and passed a formatter-only
follow-on probe. Deterministic tests and model observations remain separate.

## Compatibility and upgrade

The repository name, display name and invocation slug
`repository-operational-truth-audit` stay unchanged. Existing installations do
not auto-upgrade. The published v0.1.0 remains Audit-only and is not retagged.

Use the [README](../../README.md) to select the current stable or source-candidate
installation. Use the local installer's explicit replacement option for an
intentional upgrade and inspect its backup and receipt. Then confirm discovery
and behavior in a fresh host task. Do not announce a v0.2.0 install command as
available until its tag and Release have been verified.

## Position and limits

This is an on-demand engineering intervention, not a daily code reviewer,
automatic cleanup campaign, security scanner or replacement agent platform.
Host tools provide actual execution, permissions and containment. The optional
byte checker requires POSIX secure reads; complete native Windows operator
support is not claimed.

The evidence does not prove general autonomous production refactoring, real-data
migration, universal crash recovery or exactly-once external effects. Installation,
activation and owner acceptance must be recorded at their observed layers.

The [usage guide](../usage.md) explains requests and expected results.

changing this draft's status. Licensing and attribution remain unchanged; see
