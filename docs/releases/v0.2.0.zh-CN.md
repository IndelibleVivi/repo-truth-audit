## 相比 v0.1.0 扩展了什么

原来的 Audit-only Skill 扩展为 Audit / Plan / Operate 连续工作流。
普通检查保持只读，规划在目标编辑前停止。明确要求实施有限结构改造后，可以继续完成实现、真实调用者
与入口迁移、相关测试和文档、要求退出的旧路径、恢复感知检查点及验收。

实施始终对整个约定目标负责。第一步得到验证，只能算检查点。适用的行为、结构、交付与用途检查，
用于区分可用过渡和完整结果，也用于验证最初的开发阻力是否减轻。

## 可靠性与证据

验证、摘要、安装暂存和已安装比较共用显式八文件载荷。
普通导入产生的字节码既不改变有效载荷身份，也不进入安装包；未声明的源码与可执行项会被拒绝。
可选的有界字节检查器只验证引用字节，不证明权限、语义正确性或任务完成。

[forward 回执](../forward-0.2.0-receipt.zh-CN.md) 保留历史证据，说明早期复制目录中的字节码差异，
并记录干净载荷下真正的 Plan 和一次请求完成整体目标的 Operate 观察。
后者完成了有限合成改造，构建声明产物，通过了只修改格式化模块的后续试验。
确定性测试与模型观察继续分别报告。

## 兼容与升级

仓库名、显示名称及调用 slug `repository-operational-truth-audit` 不变。
已有安装不会自动升级，已发布的 v0.1.0 保持 Audit-only，不移动旧 tag。

通过 [README](../../README.zh-CN.md) 选择当前稳定版或源码候选。
有意升级已有安装时，使用本地安装器的显式替换选项并检查备份与回执；随后在宿主新任务中确认发现
与行为。在新 tag 与 Release 核验前，不把 v0.2.0 安装命令宣传为已经可用。

## 定位与限制

这是按需进入、做完退出的工程工具，不承担每日代码审查、自动清理运动、安全扫描或替代代理平台的职责。
真实执行、权限和隔离由宿主工具提供。可选字节检查器需要 POSIX 安全读取，不声称完整原生 Windows 支持。

当前证据不证明任意生产仓库自主重构、真实数据迁移、通用崩溃恢复或外部效果恰好一次执行。
安装、加载与所有者验收，仍需按实际观察到的层记录。
