## Changes from v0.2.0

- Assess auxiliary workflows against the actual task gap, prerequisites,
  lasting machinery and completion gates. Preserve applicable host, user and
  project requirements; decline an unsuitable complete workflow rather than
  claim compliance after skipping its required steps.
- Choose verification that can reject the relevant wrong behavior. Distinguish
  green refactor baselines, actual defect witnesses, direct retirement evidence
  and executable-gate counterexamples. Necessary regression tests remain welcome;
  a new permanent test subsystem is not an automatic prerequisite.
- Allow explicitly authorized cleanup of selected dirty implementations while
  preserving unrelated work and recoverable before-images.
- Include retained verification costs in Usefulness and judge the agreed phase.
  When completion is challenged, reconcile the request, actual diff and observed
  result. No net-line quota, per-test approval or global-minimum-cost proof is added.
- Include Windows test portability fixes merged after v0.2.0. This does not
  expand the claimed native Windows operator support.

[Issue #4](https://github.com/IndelibleVivi/repo-truth-audit/issues/4) motivated these
refinements. It remains a field report, not a confirmed failed cleanup or causal
finding against RTA or another Skill.

## Size and compatibility

The installable payload remains exactly eight files. Relative to v0.2.0:
`SKILL.md` grows from 125 to 133 lines, and the on-demand operation reference
from 171 to 209. The whole payload grows by 46 lines and 3,500 UTF-8 bytes,
from 44,441 to 47,941 bytes. Tests, fixtures and release/evaluation documents
are outside that payload. There is no new runtime mode, engine or dependency.

The invocation slug, canonical Skill path and licensing remain unchanged.
Existing installations do not auto-upgrade. After publication, use the tagged
[README installation](../../README.md), or the local installer's explicit
`--replace` path for a deliberate upgrade with a recoverable backup. Installation
and fresh host discovery are separate observations. This publication does not
upgrade the maintainer's daily Skill copy.

## Evidence and limits

The [0.2.1 forward receipt](../forward-0.2.1-receipt.md) records nine fresh model
sessions and two read-only continuations, with independent source, reconstructed
bundle and state-effect checks. It covers optional-helper contrasts, a real
false-green duplicate write, required project test-first, authorized dirty
retirement, read-only inspection and Plan, and complete/incomplete complaint
contrasts. Deterministic fixture tests are separate from these model observations.

Both baseline and candidate passed the helper comparison. Each condition ran
once; shared host instructions remained applicable, and the optional helper's
commit requirement conflicted with the tasks' no-commit scope. The evidence does
not establish superiority, cost savings, method selection without a literal
conflict, automatic discovery or general production refactoring reliability.
