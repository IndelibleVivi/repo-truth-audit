[当前状态](../current-state.zh-CN.md)。

## 相对 v0.2.0 的变化

- 根据当前任务缺口、前置条件、长期设施与完成门槛判断辅助流程是否适用。尊重宿主、用户和
  项目的实际要求；完整流程不适合时选择其他方法，不把跳过必需步骤声称为完整遵循。
- 选择能拒绝相关错误行为的验证：区分绿色重构基线、实际缺陷 witness、直接退役证据与
  executable gate 反例。必要 regression tests 继续允许，新建永久测试子系统不是自动前置条件。
- 允许显式授权的 dirty 实现清理，同时保护无关工作及可恢复的 before-image。
- 在 Usefulness 中纳入保留验证设施的成本，按约定阶段判断完成。受到质疑时重新核对请求、
  实际 diff 与观察结果；不新增净减行指标、逐项测试审批或全局最低成本证明。
- 包含 v0.2.0 后合入的 Windows 测试可移植性修复，不扩大原生 Windows operator 支持声明。

[Issue #4](https://github.com/IndelibleVivi/repo-truth-audit/issues/4) 是这些细化的动机。
它仍是现场反馈，不是已确认的清理失败，也不对 RTA 或其他 Skill 作因果归因。

## 体积与兼容性

安装载荷仍然只有八个文件。相对 v0.2.0，`SKILL.md` 从 125 增至 133 行，按需读取的
operation reference 从 171 增至 209 行。整个载荷净增 46 行、3,500 UTF-8 bytes，
从 44,441 增至 47,941 bytes。Tests、fixtures、release／evaluation 文档均不进入安装载荷。
没有新增 runtime mode、执行引擎或 dependency。

调用 slug、canonical Skill path 与许可均未改变。既有安装不会自动升级。发布后可使用
[README 的 tag 安装方式](../../README.zh-CN.md)，或本地安装器的显式 `--replace` 路径，
在保留可恢复备份的前提下主动升级。安装与 fresh host discovery 是不同观察；本次发布不会
升级维护者的日用 Skill 副本。

## 证据与限制

[0.2.1 forward 回执](../forward-0.2.1-receipt.zh-CN.md) 记录九个独立模型会话及两次只读续问，
并由协调者独立检查 source、重建 bundle 与状态副作用。覆盖可选 helper 对照、真实 false-green
双写、项目强制 test-first、授权 dirty 退役、只读检查和 Plan，以及完整／不完整结果的质疑对照。
确定性 fixture tests 与真实模型观察分开。

两版在 helper 对照中都通过。每条件只执行一次，共享宿主说明仍适用，而且可选 helper 的
commit 要求与任务 no-commit 范围冲突。因此不证明新版更优、节省成本、没有字面冲突时的
方法选择、自动 discovery 或通用生产重构可靠性。
