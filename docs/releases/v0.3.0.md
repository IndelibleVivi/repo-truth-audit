## What this release lets you ask

“Does what we built still do what we agreed?”

A repository can have tidy modules, reachable commands and green tests while
missing a promised journey, changing its meaning, or adding work the user
explicitly wanted the product to remove. Repo Truth Audit 0.3.0 reconstructs the
product agreement that still applies, then compares it with actual selected
behavior. This works for a new, small repository as well as a long-evolved one.

Provide the relevant SPEC, key decisions or a scoped development conversation.
The Skill recovers intended users, outcomes, complete journeys, constraints and
non-goals. It respects later accepted changes and explicit deferrals. Approval of
one button does not adopt an adjacent proposal; delegation of internal wiring
does not require approval of every function or file.

For example, an optional dashboard may work perfectly while dispatch now requires
the user to write a receipt, update a task and confirm it every time. The audit
traces who must do what, when, and which step blocks work. If a later owner decision
explicitly adopts those steps for a training workflow, the conclusion changes
with that decision. Less friction is not the auditor's permanent product policy.

## How it fits existing use

- **Audit** compares accepted intent with current behavior, read-only by default.
- **Plan** turns selected gaps into a finite response without editing the target.
- **Operate** implements and verifies a finite outcome when explicitly authorized.

The comparison goes in both directions: accepted intention to reachable behavior,
and existing responsibilities back to a current purpose. It separates missing
or partial journeys, semantic drift, stale claims and unjustified accumulation
from deliberate evolution, compatibility needs and missing evidence. Absence
from a specification alone is never a deletion reason.

Reports begin with the recovered product and normal-use expectations, then explain
the material gaps. Ordinary known-bug repair and code review keep their normal
workflow. There is no new mode, engine, mandatory history archive or audit backlog.

## Installation and compatibility

The invocation slug remains `repository-operational-truth-audit`. The payload is
now exactly nine files: `references/intent.md` joins the existing package as an
on-demand reference. Evaluators, synthetic panels, tests and release documents
are outside the installable payload. No new runtime dependency is required.

Use the pinned [README installation command](../../README.md#install-from-the-public-release).
Existing copies do not auto-upgrade; the local installer's explicit `--replace`
path preserves a backup. This release does not upgrade the maintainer's daily
0.2.1 copy. Installed bytes and subsequent host selection remain separate checks.
Only supplied or authorized conversation sources are in scope; the Skill does
not automatically search private chats.

Licensing is unchanged: SUL-1.0 for functional materials and CC BY-NC-SA 4.0 for
standalone public documentation and diagrams under [LICENSING.md](../../LICENSING.md).

## Evidence and limits

The [initial intent receipt](../forward-0.3.0-receipt.md) and
[follow-up receipt](../forward-0.3.0-followup.md) retain their exact payload
identities and observation boundaries. The final candidate passed 117 repository
tests, eleven intent-fixture checks and eleven corrupted-fixture counterexamples.
A reproduced query-echo evaluator hole was fixed with complete-record checks,
including no-match and state-preservation witnesses; the previous actual search
repair also passed the stronger evaluator.

Independent synthetic audits exercised natural partial assent, delegated
internals, unsupported routine work and a later-authorized contrast with identical
implementation. Ordinary bugfix/review controls did not select the Skill. Targets
also found genuine fixture defects; original reports were retained, fixtures were
corrected without rewriting their conversation evidence, and the three product
sessions were continued. Details and remaining smoke-coverage risks are in the receipts.

These bounded trials do not establish general effectiveness or superiority over
older versions. Supplied optional-catalog selection is not host implicit-discovery
proof. Loopback panel behavior was observed, not a real browser click; that panel
is only a synthetic subject and is not installed with RTA. No additional model
sessions were run for this metadata-only release.
