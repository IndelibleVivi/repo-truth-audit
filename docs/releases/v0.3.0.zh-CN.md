## 这个版本可以替你回答什么

“现在做出来的，还是不是我们说好的那个东西？”

目录整洁、命令可达、测试绿色，仍可能漏掉答应过的流程、改变含义，或把用户明确不想承担
的劳动加回来。Repo Truth Audit 0.3.0 先恢复仍然有效的产品约定，再对照实际选中的行为。
新建小仓库同样适用，不必先变成复杂的老仓库。

提供相关 SPEC、关键决定或限定范围的开发对话，Skill 会还原用户、结果、完整流程、约束
与非目标，尊重后来被接受的变更及明确延期。批准一个按钮，不会连带采纳旁边的整套建议；
把内部接线交给实现者，也不意味着每个函数和文件都需要用户另行批准。

例如，可选 dashboard 已经能看数据，派工却被要求每次先写回执、更新任务、再确认。审计会
追踪谁必须做什么、何时做、哪一步不做就不能继续。如果用户后来明确把这些步骤接受为教学
流程，结论也应随有效决定改变；低摩擦不是审计者可以永久强加的产品偏好。

## 怎样接入原有使用方式

- **Audit** 对照已接受意图与当前行为，默认只读。
- **Plan** 把选定差距变成有限方案，不修改目标。
- **Operate** 在明确授权下实现并验证有限结果。

对照双向进行：从已接受意图追到可达行为，也从现有责任追问当前用途。区分缺失或局部流程、
语义偏移、陈旧声称、无合理用途的堆积，以及合理演进、兼容需要和证据不足。仅仅没有写进
规格，不构成删除理由。

报告先说明恢复出的产品与正常使用要求，再展开实质差距。普通已知 bugfix 和 code review
继续走普通工作流；没有新增模式、引擎、强制历史档案或审计 backlog。

search 修复也通过了加强后的 evaluator。

独立合成审计覆盖自然局部接受、内部委托、未经同意的日常增负，以及实现相同而后续授权

覆盖风险见回执。

证明；合成面板观察到 loopback 行为，未执行真实浏览器点击，该面板也不会安装到 RTA 中。
